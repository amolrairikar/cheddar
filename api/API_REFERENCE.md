# cheddar API Reference

| | |
|---|---|
| **Base URL** | `http://127.0.0.1:8000` (override with `CHEDDAR_API_HOST` and `CHEDDAR_API_PORT` in the shell that runs `start_api.sh`) |
| **Authentication** | None |
| **Response format** | JSON |
| **Interactive docs** | `/docs` (Swagger UI), `/redoc`, `/openapi.json` (generated by FastAPI) |

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | [`/health`](#get-health) | Check that the service is running |
| `POST` | [`/refresh`](#post-refresh) | Load, parse and save pending emails |
| `GET` | [`/transactions`](#get-transactions) | List and filter active or deleted transactions |
| `PATCH` | [`/transactions/{id}`](#patch-transactionsid) | Edit one transaction |
| `DELETE` | [`/transactions`](#delete-transactions) | Soft-delete transactions by id |

## Running the API

```sh
# From the repo root
./start_api.sh
```

The script needs a `.env` file in the repo root with `CHEDDAR_IMAP_USER` and `CHEDDAR_IMAP_PASSWORD`. It runs the API in the background, writes logs to `.api.log` and writes the process ID to `.api.pid`. Stop it with `kill $(cat .api.pid)`.

| Environment variable | Required | Default |
|---|---|---|
| `CHEDDAR_IMAP_USER` | For `/refresh` | None |
| `CHEDDAR_IMAP_PASSWORD` | For `/refresh` | None |
| `CHEDDAR_IMAP_HOST` | No | `imap.gmail.com` (port is always `993`) |
| `CHEDDAR_IMAP_FOLDER` | No | `transactions-pending` |
| `CHEDDAR_IMAP_PROCESSED_FOLDER` | No | `transactions-processed` |
| `CHEDDAR_IMAP_FAILED_FOLDER` | No | `transactions-failed` |
| `CHEDDAR_DB_PATH` | No | `./cheddar.db` |

## Conventions

- **Money and quantities** are decimal **strings** (`"-17.99"`), not JSON numbers.
- **Amount sign:** negative means money spent, positive means money received.
- **Timestamps** are ISO 8601 strings in UTC (`"2026-11-20T18:42:07+00:00"`). Parsed timestamps come from the email's `Date` header.
- **Errors** return `{"detail": "<message>"}`. Validation errors (422) return `detail` as a [list of objects](#validationerror).

## `GET /health`

Returns the service status. It doesn't contact the mail server.

**Parameters:** none

### Sample request

```sh
curl http://127.0.0.1:8000/health
```

### `200 OK`

```json
{
  "status": "ok"
}
```

## `POST /refresh`

Processes the emails in the pending folder:

1. Downloads and parses each email.
2. Saves all parsed results in a single database transaction.
3. Moves parsed emails to the processed folder.
4. Moves downloaded emails that couldn't be decoded or parsed to the failed folder.

Emails that couldn't be downloaded stay in the pending folder for the next refresh. They still appear in `failed`.

**Parameters:** none (no query parameters or request body)

### Sample request

```sh
curl -X POST http://127.0.0.1:8000/refresh
```

### `200 OK`

`parsed[].result` is either a `transaction` or a `position_summary`. Check its `type` field to tell them apart.

```json
{
  "parsed_count": 2,
  "failed_count": 1,
  "parsed": [
    {
      "uid": "101",
      "result": {
        "type": "transaction",
        "merchant": "UBER *TRIP",
        "amount": "-17.99",
        "account": "United Quest Visa 1234",
        "timestamp": "2026-11-20T18:42:07+00:00"
      }
    },
    {
      "uid": "102",
      "result": {
        "type": "position_summary",
        "account": "Fidelity 6789",
        "snapshot_date": "2026-11-20T21:00:00+00:00",
        "balance": "2500.00",
        "positions": [
          {
            "ticker": "VTI",
            "quantity": "10.000",
            "price": "250.00",
            "value": "2500.00",
            "account": "Fidelity 6789",
            "account_type": "1",
            "snapshot_date": "2026-11-20T21:00:00+00:00"
          }
        ]
      }
    }
  ],
  "failed": [
    {
      "uid": "103",
      "reason": "unsupported sender 'news@example.com'"
    }
  ]
}
```

An empty pending folder returns:

```json
{
  "parsed_count": 0,
  "failed_count": 0,
  "parsed": [],
  "failed": []
}
```

### Response fields

| Field | Type | Description |
|---|---|---|
| `parsed_count` | integer | Number of items in `parsed` |
| `failed_count` | integer | Number of items in `failed` |
| `parsed[].uid` | string | IMAP UID of the email. This is **not** the transaction `id`. |
| `parsed[].result` | object | [TransactionResult](#transactionresult) or [PositionSummaryResult](#positionsummaryresult) |
| `failed[].uid` | string | IMAP UID of the email |
| `failed[].reason` | string | Why the email failed |

#### TransactionResult

| Field | Type | Description |
|---|---|---|
| `type` | string | Always `"transaction"` |
| `merchant` | string | Merchant or counterparty. It's `""` for Chase transfers, and `"direct deposit"` for Chase direct deposits. |
| `amount` | decimal string | Signed amount |
| `account` | string | Account label, such as `"Venmo"` or `"Chase Checking 1234"` |
| `timestamp` | string | ISO 8601 UTC |

#### PositionSummaryResult

| Field | Type | Description |
|---|---|---|
| `type` | string | Always `"position_summary"` |
| `account` | string | Account label |
| `snapshot_date` | string | ISO 8601 UTC timestamp (includes the time) |
| `balance` | decimal string | Total account value |
| `positions[].ticker` | string | Symbol |
| `positions[].quantity` | decimal string | Quantity held |
| `positions[].price` | decimal string | Price per unit |
| `positions[].value` | decimal string | Position value |
| `positions[].account` | string | Account label |
| `positions[].account_type` | string | Numeric code from the email's `Acct Type` column |
| `positions[].snapshot_date` | string | ISO 8601 UTC |

#### Common failure reasons

| Example `reason` | Email moves to failed folder? |
|---|---|
| `unsupported sender 'news@example.com'` | Yes |
| `no chase parser matches this email` | Yes |
| `amount is zero` | Yes |
| `positions do not add up to the Total` | Yes |
| `message could not be decoded` | Yes |
| `message could not be downloaded` | No (stays pending) |

### Error responses

| Status | When | Sample `detail` |
|---|---|---|
| `409` | Another refresh is already running | `a refresh is already in progress` |
| `500` | Mail credentials are missing | `missing environment variable(s): CHEDDAR_IMAP_USER, CHEDDAR_IMAP_PASSWORD` |
| `500` | Saving to the database failed. Nothing is saved and no email is moved. | `could not save results to the database` |
| `502` | Login failed | `could not log in to imap.gmail.com as you@example.com` |
| `502` | Selecting the pending folder failed | `could not select folder 'transactions-pending'` |
| `502` | Searching the folder failed | `search failed in folder 'transactions-pending'` |
| `502` | 3 emails in a row broke the connection | `connection broke on 3 messages in a row in folder 'transactions-pending'` |
| `502` | Email UIDs changed after reconnecting | `message identifiers changed in folder 'transactions-pending'` |
| `502` | Copying to a destination folder failed (for example, it doesn't exist) | `could not copy messages to folder 'transactions-processed'` |
| `502` | A connection or protocol error occurred while moving emails | `could not move messages to folder 'transactions-processed'` |
| `502` | Emails were copied, but the originals couldn't be removed | `could not remove moved messages from 'transactions-pending'` |

A `502` while moving emails happens **after** the results are saved, so they remain in the database. Running the refresh again doesn't create duplicate transactions, which are matched on the email's `Message-ID`. A position with the same account, ticker and `snapshot_date` is updated instead of added again.

## `GET /transactions`

Lists stored transactions, ordered by `id`. There is no pagination.

### Query parameters

| Name | Type | Required | Default | Description |
|---|---|---|---|---|
| `deleted` | boolean | No | `false` | `false` returns only active transactions. `true` returns **only** soft-deleted ones. |
| `start_date` | date (`YYYY-MM-DD`) | No | None | Earliest transaction date, inclusive |
| `end_date` | date (`YYYY-MM-DD`) | No | None | Latest transaction date, inclusive |
| `merchant` | string, repeatable | No | None | The current `merchant` (not `original_merchant`) **contains** the value |
| `category` | string, repeatable | No | None | `category` equals the value |
| `account` | string, repeatable | No | None | `account` equals the value |
| `tag` | string, repeatable | No | None | Any of the transaction's tags equals the value |
| `transaction_type` | `Income` or `Expense`, repeatable | No | None | `transaction_type` equals the value (case-sensitive) |

### Filtering rules

- Repeat a parameter to match **any** of its values: `tag=work&tag=shared` lists transactions with either tag.
- Different parameters must **all** match, including `deleted`.
- `merchant`, `category`, `account` and `tag` ignore case. Characters such as `%` and `_` have no special meaning.
- `merchant`, `category`, `account` and `tag` values can't be empty or only whitespace. Values aren't trimmed.
- Dates are compared with the **UTC** date of `transaction_timestamp`, so an evening purchase west of UTC can fall on the next day. Either date can be used alone.
- You can't filter for transactions that have no category or type.
- Unrecognized parameters are ignored.

### Sample requests

```sh
# Active transactions
curl http://127.0.0.1:8000/transactions

# Soft-deleted transactions
curl "http://127.0.0.1:8000/transactions?deleted=true"

# October expenses tagged "work" or "shared"
curl "http://127.0.0.1:8000/transactions?start_date=2026-10-01&end_date=2026-10-31&transaction_type=Expense&tag=work&tag=shared"
```

### `200 OK`

```json
{
  "transactions": [
    {
      "id": 1,
      "original_merchant": "UBER *TRIP",
      "original_amount": "-17.99",
      "merchant": "UBER *TRIP",
      "amount": "-17.99",
      "account": "United Quest Visa 1234",
      "transaction_timestamp": "2026-11-20T18:42:07+00:00",
      "category": null,
      "transaction_type": null,
      "tags": [],
      "deleted_at": null
    }
  ]
}
```

With `deleted=true`, each item has `deleted_at` set (for example, `"2026-11-26T17:51:44.414343+00:00"`). If nothing matches, the response is `{"transactions": []}`.

### Response fields

| Field | Type | Description |
|---|---|---|
| `id` | integer | Transaction id, used by `PATCH /transactions/{id}` and `DELETE /transactions` |
| `original_merchant` | string | Merchant as parsed (can be `""`) |
| `original_amount` | decimal string | Signed amount as parsed |
| `merchant` | string | Edited merchant, or `original_merchant` if not edited |
| `amount` | decimal string | Edited amount, or `original_amount` if not edited |
| `account` | string | Account label |
| `transaction_timestamp` | string | ISO 8601 UTC |
| `category` | string or null | Category, set with `PATCH` |
| `transaction_type` | `"Income"`, `"Expense"` or null | Set with `PATCH` |
| `tags` | string[] | Sorted by character code (uppercase before lowercase). Set with `PATCH`. |
| `deleted_at` | string or null | Deletion time. `null` for active transactions. |

Investment positions are saved by `/refresh`, but no endpoint lists them yet.

### Error responses

| Status | When | `detail` |
|---|---|---|
| `422` | `deleted` isn't a valid boolean, a date isn't a valid `YYYY-MM-DD` date, a text filter is blank, or `transaction_type` isn't `Income` or `Expense` | [ValidationError](#validationerror) list |
| `422` | `start_date` is after `end_date` | `start_date must not be after end_date` (a string) |
| `500` | The database can't be read | `could not read transactions from the database` |

## `PATCH /transactions/{id}`

Edits one active transaction. Only the fields you send change. You can call this while a refresh is running, and a later refresh of the same email doesn't overwrite your edits.

### Path parameters

| Name | Type | Description |
|---|---|---|
| `id` | integer | Transaction id, from `1` to `9223372036854775807` |

### Request body (`application/json`, required)

All fields are optional.

| Field | Type | `null` | Description |
|---|---|---|---|
| `merchant` | string | Reverts to `original_merchant` | Can be `""` |
| `amount` | decimal string or number | Reverts to `original_amount` | Signed, finite, at most 20 digits. Zero is allowed. Returned in plain notation (`"1E+3"` becomes `"1000"`). Send a string to keep trailing zeros. |
| `category` | string | Clears it | Can't be blank. Surrounding whitespace is removed. |
| `transaction_type` | `"Income"` or `"Expense"` | Clears it | Case-sensitive |
| `tags` | string[] | Not allowed | **Replaces** all tags. `[]` removes them. Tags can't be blank, are trimmed, and exact duplicates are stored once. |

Any other field is rejected, and nothing changes. This includes `id`, `original_merchant`, `original_amount`, `account`, `transaction_timestamp` and `deleted_at`. An empty object `{}` changes nothing.

Editing `merchant` or `amount` never changes the `original_*` values.

### Sample request

```sh
curl -X PATCH http://127.0.0.1:8000/transactions/1 \
  -H "Content-Type: application/json" \
  -d '{"merchant": "Uber", "category": "Travel", "transaction_type": "Expense", "tags": ["work"]}'
```

### `200 OK`

The updated transaction, with the same fields as a [`GET /transactions`](#get-transactions) item.

```json
{
  "id": 1,
  "original_merchant": "UBER *TRIP",
  "original_amount": "-17.99",
  "merchant": "Uber",
  "amount": "-17.99",
  "account": "United Quest Visa 1234",
  "transaction_timestamp": "2026-11-20T18:42:07+00:00",
  "category": "Travel",
  "transaction_type": "Expense",
  "tags": ["work"],
  "deleted_at": null
}
```

### Error responses

| Status | When | `detail` |
|---|---|---|
| `404` | No active transaction has this id (it doesn't exist or is soft-deleted) | `transaction not found` |
| `422` | The id is out of range or not an integer, the body is missing or isn't a JSON object, a field isn't allowed, or a value is invalid | [ValidationError](#validationerror) list |
| `500` | The database update failed. Nothing changes. | `could not update the transaction in the database` |

## `DELETE /transactions`

Soft-deletes transactions by id. The rows stay in the database and can be listed with `GET /transactions?deleted=true`. No endpoint restores them yet. You can call this while a refresh is running.

### Request body (`application/json`, required)

| Field | Type | Required | Description |
|---|---|---|---|
| `ids` | integer[] | Yes | Transaction ids to delete. Can be empty. Duplicates are processed once. Numeric strings such as `"1"` are converted to integers. |

```json
{
  "ids": [1, 2, 9999]
}
```

### Sample request

```sh
curl -X DELETE http://127.0.0.1:8000/transactions \
  -H "Content-Type: application/json" \
  -d '{"ids": [1, 2, 9999]}'
```

### `200 OK`

This example assumes transactions 1 and 2 are active and 9999 doesn't exist.

```json
{
  "deleted": [1, 2],
  "not_found": [9999]
}
```

| Field | Type | Description |
|---|---|---|
| `deleted` | integer[] | Ids deleted by this request |
| `not_found` | integer[] | Ids that don't exist or were already deleted |

Unknown ids don't cause an error; the response is still `200`. An empty `ids` list returns two empty lists.

### Error responses

| Status | When | `detail` |
|---|---|---|
| `422` | The body is missing or malformed, `ids` is missing, or a value can't be converted to an integer | [ValidationError](#validationerror) list |
| `500` | The database update failed. Nothing is deleted. | `could not delete transactions from the database` |

---

## ValidationError

FastAPI returns this format for `422` responses, with two exceptions where `detail` is a string:

- `start_date must not be after end_date`, from `GET /transactions`.
- `text must be valid Unicode`, from any request body whose rejected value contains an unpaired Unicode surrogate, such as `"\ud800"`. Nothing changes. For example, sending `{"ids": ["a"]}` returns:

```json
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["body", "ids", 0],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "a"
    }
  ]
}
```

| Field | Description |
|---|---|
| `type` | Error code, such as `missing`, `int_parsing` or `bool_parsing` |
| `loc` | Where the error is: `path`, `query` or `body`, followed by the field name and list index if they apply |
| `msg` | Readable error message |
| `input` | The rejected value |
